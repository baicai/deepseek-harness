## 首次使用

1. 在 Windows 10/11 x64 安装评估版，使用**原生 DSH 登录与模型**。
2. 将贸号 AI 鼠标通过 USB 2.4G 接收器或 BLE 连接，并确保未被原贸号鼠标助手独占。
3. 首次语音使用，在插件内打开 Voice Input 相关设置并**显式**下载准备本地 SenseVoice 模型（模型下载不静默进行）。
4. 在 DSH 工作区建立或打开当前 Session；输入框须无未发送文字和附件。
5. **单击 AI 键**：应聚焦已存在的 DSH 工作区，无第二主窗口。
6. **长按鼠标麦克风／语音键（SDK `speech`）说“给我列一个会议议程”**：应出现“正在聆听”；**松开**后做本地 SenseVoice 识别，成功则自动提交给 DSH Agent。`ai/down` + `ai/up` 作为兼容入口，但部分固件仅在语音键按下时发送 PCM，所以优先使用语音键。
7. **再次长按语音键说“把第二项细分成三个小点”**：应在相同 Session 里承接上一轮上下文，不新建会话；如出现“未收到足够的鼠标音频”则检查 SDK 音频通道，而不是反复尝试新建会话。
8. 模型如需修改文件或执行工具，必须仍按 DSH 原生审批机制由用户确认。

## 真机验收必测

- 型号/固件、SDK 默认 VID/PID 匹配、USB/BLE 连接和断开/恢复。
- `speech/down`、`speech/up` 以及 `ai/down`、`ai/up`、`ai/click` 真实事件顺序，分别核验语音键与 AI 键；短按不会误发指令、语音键长按**确实**触发鼠标自身 PCM 流。
- 无声、过短、ASR 不就绪、音频超限、切 Session、原输入框已有文字、录音中掉线、多鼠标并存，都不能误发送或崩溃。
- 长按唤醒时 DSH 最小化、后台运行、第一次没有当前 Session 时的行为；首版尚需真机结果确认。
- 原版 DSH 工作区、账号、模型、Agent 工具权限回归；DSH 无鼠标时仍可使用普通功能。
- 同机安装旧版本与 DSH-maohao Evaluation，升级、卸载、用户数据目录均不得冲突；安装包内 SDK DLL/FFmpeg 依赖和第三方许可证齐全。

## 范围与缺口

- 当前代码支持 **DSH 内语音键按住说话**及 AI 键唤醒／兼容录音；翻译、语音键**跨应用全局听写**、截图和 M 键宏不在首版范围。
- SDK 文档虽支持音频回调，但 AI 键长按期间是否有音频由客户实物固件决定，不能以软件事件模拟冒充真机成功。
- CI Windows 构建成功 ≠ 设备通过验收；真实设备连接、ASR 和 Agent 执行必须单独标明证据。
- 未审批的品牌联名措辞不能出现在公开安装包、市场页面或下载发布中。

## 安全/隐私

- 仅有实体 `speech` 或 `ai` 键按下时的 PCM 能穿过主进程 IPC；录音被内存限流、超时和会话清理，默认不写文件，不包含 SN 或音频日志。
- 原生 SDK 使用独立 `umouse-bridge.exe` 子进程隔离 DLL 异常；SDK 丢失时原 DSH 仍可打开。
- 用户本来录入的草稿和附件不会被硬件音频覆盖或意外提交，输入状态冲突直接取消自动发送。
